# 双路无刷电机闭环控制

使用 `g431_dual_motor`，两台电机均为 GB2806、7 极对、12V，每路配 AS5600 PWM 和 MiniFOC。同一套 `Application`、`MotorHardware`、`PwmSensor` 和网页控制组件各实例化两份，保留原单路位置、速度、拖动和保护逻辑。

## 接线

| 信号 | 电机① | 电机② |
| --- | --- | --- |
| MiniFOC IN1 | PA8 | PA6 |
| MiniFOC IN2 | PA9 | PA7 |
| MiniFOC IN3 | PA10 | PB0 |
| MiniFOC EN | PB5 | PB12 |
| AS5600 OUT/PWM | PA0 | PB7 |
| 驱动 nFAULT（可选） | PB4 | PB13 |
| 电机三相线 | 驱动① A/B/C | 驱动② A/B/C |

两个驱动接 12V，编码器沿用已验证的外部 3.3V 接法，所有 GND 与 STM32 共地。没有接 nFAULT 时，输入的内部上拉不代表能检测该驱动的故障。TTL RXD→PA2、TXD→PA3、GND 共地，TTL 供电脚不接。

STM32duino/Core 2.12、SimpleFOC 2.4.0 的 PWM 搜索自动选择非互补的 TIM1_CH1/2/3 和 TIM3_CH1/2/3。驱动使用普通 PA6/PA7/PB0 编号，不能将 HardwareTimer 的 ALT 用法直接套在 SimpleFOC 的搜索接口上。初始化还核对实际 PWM 参数必须为预期计时器与通道；TIM2/TIM4 预留给编码器，避免被 PWM 搜索占用。PA0 捕获 8MHz、PB7_ALT1 捕获 4MHz。

## 使用

```sh
python3 tools/stm32.py upload --env g431_dual_motor
python3 tools/stm32.py dashboard --port /dev/cu.wchusbserial1110
```

刷新 http://127.0.0.1:8840/，会显示“电机①”和“电机②”两个工作台。串口路径按实际设备选择。

1. 在对应工作台点击“校准 FOC”，该路电机会短距离正反转。
2. 待该路显示已校准、已停止，按需设零和设置软限位。
3. 选择位置保持或恒速旋转，填写参数，点击该路“启动并保持”。
4. 位置模式启动后可实时拖动目标，松手保持；每路移动速度按各自启动时的设置。
5. “立即停止 / 关闭 EN”只停止对应一路；需要全停时分别停止两路。

两路可分别校准、独立运行，也可同时运行。每路各有零点、方向、电角度、目标、控制器积分状态、限位、命令编号和 1500ms 通信租约。刷新或重连不会自动接管旧运动。当前仍为电压模式 FOC，无电流环；两路沿用原 6V 调制幅度上限、1V 校准及 0.1～10rpm 目标速度范围。上电或重新烧录均为 EN 关闭、未校准，校准结果不持久化。

## 组件与协议

- `closed_loop_main.cpp`：唯一 UART 接收器，按电机编号分派；唯一 `BoardWatchdog` 管理整板启动和运行期限。两路驱动初始化完成后才缩短看门狗期限，避免第二个驱动的阻塞初始化触发复位。
- `closed_loop_hardware.*`：引脚与捕获回调配置化，每个实例独占自身驱动、传感器和 EN。每路编码器丢失、超速或软限位仅停止该路。整板卡死或看门狗复位会影响两路。
- `closed_loop_app.*`：每路独立策略、对齐、请求高水位、租约和调试状态。双路构建不再运行之前的辅助只读监视器，PB7 成为第二路换相反馈。
- `telemetry.py`：两个 `ClosedLoopChannel`；`motors[0/1]` 对应各自反馈和状态，根 `closed_loop` 保持第一路，兼容原入口。
- `motor-workbench.js`：第二路状态投影与 API 适配，复用原 `ClosedLoopPanel`。第二路返回的状态不会覆盖根第一路，两个面板各有自己的心跳和拖动队列。

| 接口 | 电机①（兼容原单路） | 电机② |
| --- | --- | --- |
| 命令 HTTP | POST `/api/foc` | POST `/api/foc/2` |
| 心跳 HTTP | POST `/api/foc/heartbeat` | POST `/api/foc/2/heartbeat` |
| UART 请求 | `FOC,<id>,...` | `FOC2,<id>,...` |
| UART ACK/NACK | `#FOC_ACK` / `#FOC_NACK` | `#FOC2_ACK` / `#FOC2_NACK` |
| 状态 v4 | `#FOC_STATUS,4,...` | `#FOC2_STATUS,4,...` |
| 角度 | 原 `OK,...` | `#ENCODER_AUX,1,2,OK,...` |

JSON 动作和参数仍复用原验证器。停止、ACK 超时和通信写失败只清除选定电机的租约；断开唯一串口会清除两路。不同电机允许相同请求编号，ACK 与心跳按通道隔离。RX 缓冲增加至 256 字节承接两路突发；双路调试 TRACE 各降为 10Hz，整帧空间不足时丢弃调试记录，控制和 PWM 捕获频率不变。

## 2026-10-24 验证

- 新增协议电机编号、同编号不同通道 ACK、独立停止/所有权、第二路心跳、第二路传感器有效性校验、断线及非法编号测试。
- 真实伪串口 HTTP 测试验证 `/api/foc/2` 发出 `FOC2`，第一路同编号 ACK 不能完成第二路请求。
- 网页组件测试验证第二路状态投影和 HTTP/心跳路由，不改第一路全局状态；原位置、速度、拖动、租约测试保留。
- ST-Link 双路固件烧录校验通过，TIM1/TIM3 驱动初始化通过，两路编码器有效、故障 NONE、EN 均关闭。
- 浏览器实板分别点击两路停止：均收到该路 STOP ACK；第二路停止不改变第一路命令状态。切换第二路速度模式、改为 1rpm 后，第一路仍为位置模式、原 10rpm 设置。
- 85 项 Python 测试、六套 C++ 原生测试和五组网页组件测试通过；单路回退环境编译通过。390px 网页宽度下两套面板均完整显示，无横向溢出。

本轮未自动执行实物校准、位置运动或双路同时旋转；完整运动验收需按上面的工作台流程分别校准后进行。单路回退环境 `g431_closed_loop` 保留，可控制第一路并显示第二颗编码器。

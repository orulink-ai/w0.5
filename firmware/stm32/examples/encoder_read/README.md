# AS5600 PWM 角度读取（SimpleFOC）

> 单轴电机控制请使用独立的 `g431_closed_loop` 环境，支持v3位置／速度闭环、显式校准和持续运行租约，见 [控制说明](../../../../docs/closed-loop-architecture.md)。下文默认描述只读编码器环境；“无电机输出”不适用于闭环电机环境。原开环点动 `g431_motor_gpio` 保留作回退。

状态：主机测试、USB/UART/回环构建及板上回环通过；真实 AS5600 PWM 约 460Hz 已读通，用户确认转轴转动时角度跟随、停下后基本稳定。尚未做完整量程、零位与精度标定。

## 工程配置

- 芯片：STM32G431CBT6，LQFP48；使用本地板型定义，选择 T 封装 variant。
- PlatformIO Core 6.1.19、ST STM32 平台 20.0.0、STM32duino 2.12.0（framework 包 4.21200.0）、SimpleFOC 2.4.0。固定 2.x Core，避免 3.0 的定时器和串口接口变化导致编译失败；平台 20 提供此 framework 构建脚本所需的独立 CMSIS-DSP 包。
- 内部 HSI16 时钟，不依赖未确认频率的外部晶振；该配置仅用于编码器验证。
- PA0 配置为 TIM2_CH1 AF1 输入，不启用内部上下拉。TIM2 使用 8MHz 计数（0.125µs/tick），CH1 上升沿捕获周期并复位计数器，CH2 间接捕获同一个输入的下降沿；无需 CubeMX `.ioc`。当前 HSI16 / CKD_DIV1 配置使用 DTS/2、连续 8 次采样的输入滤波：采样间隔 0.125µs，约 1µs 脉冲确认时间。上升沿、下降沿和复位触发使用相同滤波配置。
- 解码保留原始高电平/周期计数；`high_us`、`period_us` 仅供兼容现有整数微秒遥测，不用于高分辨率角度计算。旧的微秒输入解码接口仍兼容，超时仍以 `micros()` 判断，支持时间戳回绕。
- 计数器和输入滤波原先分别为 1MHz、DTS/32。只提高计数器会留下原滤波器约 2µs 的边沿量化，因此本次一起调整。在约 460Hz PWM 下，单个计时 tick 对应的角度增量从约 0.176° 降为 0.022°；这是读取链路的量化步长，不是电机定位精度。编码器仍是 12 位（360°/4096≈0.088°），输出仍约 460Hz，不会因此提高传感器自身精度或更新频率。
- 此次改动以本地测试和固件编译验证，尚未烧录或实机验收。更短的滤波会允许原先可滤除的部分短毛刺通过；下次上板需对比静止抖动、慢转连续性、PWM 周期/丢帧及电机运行时的干扰。不能把显示小数位或测试中的理想计时误差当作实测精度。
- 默认 `g431_as5600_usb`：PA11/PA12 原生 USB CDC，使用 HSI48 + USB SOF 时钟校准；需要开发板 Type-C 数据线确实接到 MCU。
- 备用 `g431_as5600_uart`：PA2 = USART2 TX，PA3 = USART2 RX，115200、8N1。
- PA13/PA14 保留 SWD，ST-Link 下载；不创建电机/驱动对象，不输出电机 PWM。

## 接线（先只接主控与编码器）

先断开 MiniFOC 的 12V 电源和控制线。本例没有驱动使能管理，不能作为电机控制固件使用。

| AS5600 模块 | STM32 开发板 |
| --- | --- |
| OUT / PWM | PA0 |
| GND | GND |
| VCC | 仅当模块明确支持 3.3V 供电时接板上 3V3 |

必须确认模块的供电脚定义，不能仅凭芯片支持 3.3V 就假定任意模块 VCC 的接法相同。PWM 信号应为 3.3V 电平；若模块必须以 5V 供电，先核对原理图并使用合适的电平转换。不要将 12V 接到编码器或 STM32 的 3V3。

模块必须已设置为 PWM 输出，且使用完整 360° 输出范围。本例不通过 I²C 改写配置，也不烧写 OTP。AS5600 默认 OUT 可以是模拟输出；没有 PWM 时本例只报告异常，不能单凭该报告认定模块损坏。

磁铁须固定在被测转轴上，对准传感器中心；手动慢转验证。单靠 PWM 波形不能可靠判断磁场强度或磁铁诊断位，需要时另接 I²C 读取状态寄存器。

| USB 转串口模块（3.3V 逻辑） | STM32 开发板 |
| --- | --- |
| RXD | PA2（TX） |
| TXD，页面目标按钮必接；只看日志时可不接 | PA3（RX） |
| GND | GND |
| VCC | 不接，开发板使用自己的正常供电 |

优先直接使用开发板 Type-C：默认固件启用 USB CDC，烧录后若数据通路正常，Mac 应出现 `/dev/cu.usbmodem...`。此时无需外接转串口模块，PA2/PA3 也不参与日志输出。仅插 Type-C、但尚未下载 CDC 固件时，不能据此判断 USB 接口是否可用；须使用数据线。

ST-Link 继续接 GND、DIO/SWDIO、CLK/SWCLK，可加 NRST。Type-C 负责供电/日志，ST-Link 负责下载；不要将两路电源输出并联。若 Type-C 最终确认仅供电，则按上表接外部 USB-UART，并使用 UART 备用环境。没有转串口时也可用 ST-Link 调试器查看全局 `encoder_debug`，未提供自动读 RAM 的工具。

## 实现与验收

`src/pwm_input.cpp` 封装 TIM2 硬件输入捕获，周期和脉宽来自 CCR1/CCR2，不再用 GPIO CHANGE 中断中的 `micros()` 差值测量。上升沿中断提交读数，主循环在短临界区复制；缺失下降沿、捕获覆盖和首帧均不可作为有效角度。`../../lib/as5600_pwm/as5600_pwm.h` 不依赖 Arduino，负责帧有效性、周期/占空比检查和信号过期判断。`micros()` 仅用于信号新鲜度判断，不参与脉宽/周期计算。有效范围覆盖 AS5600 的 115/230/460/920Hz 设置，不把输出频率固定成 920Hz。

角度按 `count = clamp(high / period * 4351 - 128, 0, 4095)`、`angle = count / 4096 * 2π` 换算，包含帧头偏移。未针对模块做零位、频率抖动或精度标定；极限值附近会钳位。SimpleFOC 的 GenericSensor 消费该机械角度，处理跨圈及角速度；之后可将同一传感器接口链接到电机，故障处理仍须由电机状态机实现。

主循环高频更新，每 100ms 输出一行：

```text
status,angle_deg,velocity_rad_s,frequency_hz,high_us,period_us
OK,123.45,0.000,919.1,389,1088
NO_PWM_OR_INVALID,nan,nan,nan,389,1088
```

每秒额外输出 `#CAPTURE,frames=...,overruns=...,complete=...,PA0=...`，分别表示累计上升沿回调数、累计捕获覆盖帧数、最后一帧是否完整和当前输入电平。这些诊断行只显示在网页原始日志中。

数值仅示例。`angle_deg` 是 0～360° 单圈机械角，不是电角度；静止时应基本稳定，慢转一圈应覆盖一圈并从 360° 附近回到 0°，反向慢转时速度符号应改变。速度为读数估计，初次采样和信号恢复时不作为稳定速度验收。

断开 OUT 后应在约三个 PWM 周期（约 3～30ms）内使 `encoder_debug.valid` 变为 0，并在下一次日志输出时报告 NO_PWM_OR_INVALID，不把旧角度作为当前有效值打印。恢复后重新初始化 SimpleFOC 的速度和圈数历史；断线期间的转动无法补算。异常日志中的 high/period 是最后测量值，不代表新鲜信号。

若始终异常，依次检查共地、PA0 接线、OUT 实际输出模式和电平、磁铁对中；有示波器时确认 OUT 存在脉冲。不要改接 SDA/SCL 并期待其输出 PWM。

## 已知 PWM 回环对照（排查代码/输入链路）

`g431_pwm_loopback` 是独立的 UART 自检构建，正常的 USB/UART 编码器构建不会启用该输出。自检由 TIM1_CH1 从 PA8 输出 250Hz、50% 占空比，经外部跳线送入相同的 PA0/TIM2 捕获和 SimpleFOC 读数路径。

1. 断开电机驱动电源及 PA8 上的驱动控制线。
2. 断开 AS5600 OUT→PA0；不能将编码器 OUT 与 PA8 两个输出直接连接。
3. 单根跳线连接 STM32 PA8→PA0。编码器地线可保留，板上 GND 不变。
4. 接线确认后执行：

```sh
python3 tools/stm32.py upload --env g431_pwm_loopback
```

预期页面频率约 250Hz、周期约 4000µs、高电平约 2000µs、角度约 179.96°、静止速度接近零。角度不是刚好 180°，因为相同解码路径包含 AS5600 的帧头偏移。若对照通过，验证的是该已知波形下的硬件捕获、解码及显示链路，不能代替编码器供电、输出模式、磁铁安装的验收。

完成后移除 PA8→PA0 跳线，恢复正常构建 `g431_as5600_uart`，再将编码器 OUT 接回 PA0。先停止自检输出再恢复编码器接线。

2026-10-24 用户再次确认外部电源 GND 已与 STM32 GND 连接且重新上电；网页/串口仍正常，但捕获计数停在 60247、PA0 持续高电平，尚无新的 PWM 帧。已准备回环构建，待实际接线后烧录验证；不将前面断电/缺少地线时的跳动读数当作角度验收。

回环首轮实测：自检固件已通过 ST-Link 烧录并校验。TIM1 输出寄存器确认 PSC=0、ARR=63999、CCR1=32000、CH1/MOE 已使能，PA8 为 AF6；HSI16 下对应 250Hz/50%。TIM2 输入却测到约 19979µs 周期、6907µs 高电平。随后在目标持续运行时，通过 SWD 连续 40 次读取同一个 GPIOA_IDR 寄存器，同时比较 PA8（bit8）和 PA0（bit0），有 19 次电平不一致。若两脚由跳线直接可靠短接，电平应一致；该证据指向跳线接触、引脚位置或板上通路问题，而非角度换算。已请用户绕过面包板，换线直连 PA8→PA0 后复测。当前芯片仍为回环固件，编码器 OUT 必须保持与 PA8/PA0 隔离。

换线后第二轮：PA8/PA0 同寄存器电平比较 40 次中有 21 次不同，TIM2 仍主要测到约 20ms 周期。进一步临时将 PA8 切为 GPIO 输出做静态通断对照：PA8 强制低、PA0 弱上拉时读到 PA8=0/PA0=1；PA8 强制高、PA0 弱下拉时读到 PA8=1/PA0=0。PA0 随自身弱上下拉而变化，未跟随 PA8，说明 MCU 两脚之间当前没有可靠的低阻连接；待照片核对实际引脚、插接与排针焊接通路。测试后已移除 PA0 内部上下拉并将 PA8 恢复 AF6 的 TIM1 输出，未更改 Flash。编码器功能尚未验收。

回环最终验收：用户确认此前接错线，修正后连续四次每秒快照均为 `OK,179.91,0.000,250.1,1999,3999`；同一次 GPIOA_IDR 同时比较 PA8/PA0 的 40 次采样全部一致，且 PA8 高/低均有覆盖。该已知信号下的 TIM2 输入捕获、AS5600 比例解码、SimpleFOC 机械角/静止速度和 UART/网页链路通过对照；1µs 量级的计数偏差未做标定，不代表实际 AS5600 已验收。之后已重新烧录并校验 `g431_as5600_uart`，关闭 PA8 自检输出；等待移除 PA8→PA0 跳线，将 AS5600 OUT 接到这次验证过的 PA0，保留外部电源 GND 与 STM32 GND 共地，再验收编码器。

恢复真实编码器：用户已拆除回环线，将 OUT 接回验证过的 PA0，并确认外部供电与 STM32 共地。连续五次每秒快照均无效；TIM2 回调数停在 5066、PA0 为低，6509µs/15113µs 为旧值。用户确认磁铁已对准芯片中心并随轴转动；模块没有或未找到 SDA/SCL，因此没有继续实现/烧录 I²C 诊断，更没有读取或改写实际传感器配置。下一步需模块正反面、当前接线照片及模块 VCC-GND 实测供电电压，以确认引脚和供电方式。当前保持正常 UART PWM 读角固件。

## 当前实测结论（2026-10-24）

真实 AS5600 PWM 读取已跑通。用户确认 OUT 接到回环验证过的 PA0，编码器外部 3.3V 供电，外部 GND 与 STM32 GND 相连；PA8 回环线已移除，当前固件为 `g431_as5600_uart`，没有 PA8 测试输出。

连续采样显示频率约 459.3～459.8Hz、周期 2175～2177µs，与 460Hz 档相符。观察到角度约 219.74°逐渐变化到 85.54°，用户确认当时在手动转轴，停下后基本稳定。随后四次每秒快照均为有效读数，角度 61.65°、61.65°、61.30°、61.58°，周期 2177～2179µs。该短时静止样本角度跨度约 0.35°，不是绝对精度标定。

因此当前已确认：该模块有可解码 PWM、PA0 硬件捕获/解码/SimpleFOC 读角/UART/本地页面链路可工作。此前缺少公共地线、回环线接错引脚是已确认的接线问题；此前修复的角度换算错误也保留回归测试。没有读取 CONF/STATUS，也没有改写传感器寄存器或 OTP。原始速度由帧间角差直接计算，小角度量化会放大为速度波动；本阶段验收角度显示，电机控制和速度滤波尚未实现。

## 网页目标按钮（暂存，不驱动电机）

当前 UART/USB 固件接收 `TARGET,<request_id>,<degrees>` 行，协议实现位于 `../../lib/angle_target/angle_target.h`，与 PWM 解码及 Arduino 分离。接收缓冲上限 47 字节，每次主循环最多处理 64 个串口字节，只有完整且合法的行才更新暂存目标；不接受 ARM/ENABLE。确认输出 `#TARGET_ACK,<request_id>,STAGED,<degrees>`，重复编号同目标幂等，重复编号不同目标返回 ID_CONFLICT；错误/超长行不改变目标。

启动时 PB5 配置为低电平输出并始终保持低，不初始化电机驱动和电机 PWM。用户当前实物 EN 接 GND，12V 已供电；页面显示“电机未使能”，四按钮只验证命令链路。`#CONTROL,1,DISABLED,<request_id>,<degrees>` 每秒报告当前暂存状态；启动后目标为 -1，既不持久化，也不自动执行复位前的目标。

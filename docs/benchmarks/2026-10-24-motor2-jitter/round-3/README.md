# 电机②网页端到端运行时诊断（续测）

2026-10-24，Asia/Shanghai。网页 → HTTP → CH340 命令/ACK → STM32 控制输出 → AS5600②反馈；同时用 ST-Link 只读采样。未改变控制参数或烧录固件，未重新校准。

## 观测结论

这次约 13.8 秒的使能过程没有捕获明显往复角度摆动。第二路编码器从目标开始到结束一直在 **-64.093°附近**，951 个运行期间 SWD 角度样本的总峰峰值 **0.139°**，标准差 **0.019°**。关闭使能的基线标准差约 **0.018°**，两者相近。

目标增加 8° 后，MCU 已接收指令，PB12 输入回读和输出寄存器都为高，TIM3 已采集的两个 PWM 比较寄存器随电压指令变化。Uq 指令最高 **3.458V**，反馈仍未出现相应的 8°位移。这是目前最明确的异常，尚不能据此确定供电、驱动/相线、机械耦合或校准中的哪一项导致。

| 阶段 | 目标 | 反馈角度（UART TRACE） | 电压指令 Uq |
|---|---:|---:|---:|
| 当前位置保持，约2.3s | -64° | -64.132～-64.044° | 接近0V |
| 目标增加8°，约6.2s | -56° | -64.132～-64.044° | 约0.27→3.43V |
| 目标返回，约5.4s | -64° | -64.149～-64.061° | 约3.05～3.27V |

返回目标后 PI 积分仍约 3.24V，是上一阶段持续位置误差累积的控制状态；它说明控制器在持续施加校正指令，不能证明实际相电压、电流或力矩已输出。尚未达到6V软件上限，也未捕获持续饱和或实际大幅振荡。没有充分证据直接增加电压或认定 PID 是根因。

## 链路核对

- 浏览器真实填写目标、点击“启动并保持”、修改目标、点击停止；事件见 `browser-events.json`。
- UART 收到 POSITION、两次目标更新及 STOP 的 ACK；输入/change 都触发目标发送，同一目标出现两次 ACK 属当前网页行为，此次没有目标往复交替。
- 运行中 PB12 的 MCU 输入回读/输出寄存器均为高；停止后均为低。只能证明 MCU 端电平判定，不能代替驱动板 EN 端实测。
- TIM3 ARR=319，CCR1/CCR2 在步进阶段分别约167～250、116～156；停止后均为0。**本次连续读数没有包含 CCR3**，不能据此声称三相实际电气输出都正确。
- 编码器② API 未报告无效帧；其角度读取来自 PB7 对应 tracker，每帧 sequence 持续更新。AS5600 读数稳定不能证明磁铁机械连接、磁场及绝对角度标定均无误。
- 电机①整个采集中保持关闭，命令 id 未变化。

## 日志与方法

- `serial.jsonl`：原始串口消息；电机② TRACE 共139条，约10Hz。
- `swd-raw.log`：2000条运行时读取，平均间隔14.66ms，约68Hz；运行期间角度采样951条。
- `swd.csv`、`trace.csv`：解码结果；`summary.json`：统计；`analyze.py`：可复现分析。
- `states.jsonl`、`before.json`、`after.json`：API 状态；`events.json` 的边界按API第一次观测变化恢复，存在通信延迟。
- `capture.py`、`capture-swd.tcl`：本次采集程序。采样结束清理 OpenOCD 时等待超时，停止操作已先成功执行；随后 OpenOCD 完成2000条读取并输出 shutdown。原始文件已完整保存，状态和事件已单独补存。无 OpenOCD 遗留进程。
- 在使能阶段未执行 halt、reset、flash 或写目标内存。沿用上次仅离线推导的 RAM 成员布局，详见上级 `debug-build.json`；未把不同机器码的调试 ELF 当作已烧录代码。
- 时间为主机接收/读取时间，多变量不是原子快照。本采样率**不能排除更高频或小于角度测量噪声的机械振动**；软件 Uq 指令不等于实际电压实测值。未采集12V母线、电流或相线波形。

## 后续定位方向

已用第二路反馈确认：本次目标变更没有带来明显轴位移，未复现可观测的大幅角度抖动。应核对电机②驱动的12V、实际EN及相线连接，以及AS5600②是否随该转轴运动；反馈对应正确且供电/接线可靠后再检查FOC校准及速度环参数。

结束状态：两路 READY / EN关闭 / fault NONE，校准保留。此前 `round-2` 因网页输入框不可见而未启动，仅为无运动基线；不计为成功的运动测试。

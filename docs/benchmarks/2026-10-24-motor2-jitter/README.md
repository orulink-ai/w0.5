**最新结果：电机②持续抖动已修复并固化烧录。仅调整②的输出变化率为100V/s、速度P为0.10；最终拖动/保持复测稳定波动0.07～0.32°。详见 [最终修复与验收](STABILIZED.md)。以下保留首次短测记录。**

## 结论

本次短测没有捕获明显往复振荡，不能据此确定用户报告的抖动根因。捕获到的是“目标已更新，但反馈几乎不动，速度 PI 积分逐渐累积”。应先确认本次测试时驱动②的 12V、使能及实际机械运动，再决定是否调整控制器。

| 阶段 | 指令 | 实际反馈 | 控制输出 |
|---|---|---|---|
| 保持约 2s | 9° | 9.105～9.158° | Uq -0.025～0V |
| 小角度移动约 4s | 12° | 9.036～9.149°，平均误差 2.879° | Uq 约 0.099→0.883V |

- 小角度移动时，84 条编码器记录中的该阶段 40 条均有效，PWM 为 457.6～457.9Hz。没有发现丢帧状态或大幅角度跳变；这不证明编码器绝对角度、安装和磁场均无误。
- ST-Link 采样显示：该阶段速度积分项最高约 0.804V，控制器滤波速度约 -0.270～0.114rad/s，快速编码器估计约 -0.182～0.243rad/s。速度噪声存在，但本次没有观察到大幅反复换向的 Uq。
- Uq 最高约 0.889V，远未达到当前 6V 软件上限；“电压上限不够”没有在本次记录中得到支持。小步进在角度环中只产生约 0.4rad/s 的速度目标，因此不能将本次测试当作满输出带载能力测试。
- TIM3 的 PA6/PA7/PB0 复用和三路 PWM 配置符合当前实现，未发现 TIM4 编码器捕获被 PWM 占用的迹象。寄存器检查不是实际三相波形或电流测量。
- 未触发超速、传感器或驱动锁存故障。可选 nFAULT 若未接线，软件“无故障”并不能排除驱动故障。

## 可证实的现象与待验证原因

1. 确定：位置指令已到达 MCU；位置反馈几乎保持不变；PI 积分随误差累积。
2. 尚未确定：驱动缺少 12V/未实际使能、相线接触、机械负载/静摩擦、编码器与被控转轴对应关系、校准偏差等均可能产生类似记录。
3. 如果实际电机在动而角度不变，优先核对第二路编码器是否跟随同一转轴；如果电机不动，先核对驱动供电/EN及三相线。
4. 积分累积后突然克服阻力可能导致突跳或反复纠偏，但本次没有捕获这一过程，不能将其写成已确认根因。也未排除较高频率的电气或机械抖动。

## 采集方式与限制

- CH340：记录真实串口消息 318 条，其中电机② TRACE 61 条，约 10Hz。
- ST-Link：不暂停 CPU，以 OpenOCD `read_memory` 连续读取运行时 RAM 600 次，平均间隔 17.843ms（约 56Hz）。读取不是多变量原子快照，不能用于精确环路时序或高频振动分析。
- 另存 HTTP 状态快照 154 条与阶段事件时间。串口的 host 时间是服务器接收时间，存在传输/排队延迟。
- 未写入测试固件。额外构建 `-g3` ELF 只用于离线查找成员布局；它与已烧录固件机器码不同，未用于源码断点/PC定位。原始及调试 ELF 的第二路对象地址和大小一致，并用现场 6V、P=0.2、I=0.5、方向=-1 常量校验。见 `debug-build.json`。结束后恢复本地原始 ELF/BIN。
- STOP 后的 motor 对象字段保留旧值，不代表 EN 关闭后仍有实际桥输出。分析运动输出仅使用使能阶段数据。
- ST-Link 的约 3.25V 是 MCU 目标电压，不能据此推断电机 12V 母线稳定；未采集电流或母线电压。

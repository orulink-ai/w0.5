# FOC校准端点过早采样修复

2026-10-25。已修复、烧录，并通过电机②连续三次校准及小角度定位/返回验证。

## 问题与改动

旧流程在正向扫动1秒、反向扫动约1秒结束的瞬间保存角度。即使稍后等200ms再检查，比较的仍是提前保存的值。转子有跟随滞后时，测得行程偏小。故障现场读取的44.673°略低于原允许下限44.880°，因此触发并锁存ALIGNMENT_FAILED。

新Alignment仍是纯逻辑、非阻塞状态机：初始对齐500ms → 正向扫动2s → 保持600ms后保存mid → 反向扫动2s → 保持600ms后保存end并校验 → 零位保持700ms后完成。正常约6.4秒，累计9秒超时失败。

每个阶段从实际进入时刻计时，每次tick最多转移一个阶段，延迟轮询不会跳过端点保持。输出在采样前保持端点电角度，采样后再换向。保留1V校准电压、7极对以及原0.8rad电角度偏差容限；原堵转/极对数检查、STOP、反馈失效、看门狗和1500ms通信租约继续有效。网页说明更新为约6.4秒，运动控制器的两路独立增益未改变。

从网页实际点击初次校准，随后两次重新校准；同时读取UART状态和ST-Link运行时字段，采样时未暂停CPU。

三次行程电角度偏差约0.170～0.173rad，均小于原0.8rad门槛；方向均为-1。MCU阶段计时约6.4秒，浏览器时长包含通信与页面刷新延迟。过程中电机①未启动。

校准后使用网页执行10.5°→15.5°→10.5°。正向定位后平均误差约+0.142°，返回记录的平均误差约-0.048°，无故障。返回后前段仍有收敛过程：2秒后窗口峰峰值0.583°，末1.5秒峰峰值0.116°、标准差0.033°；本次不将小角度验证表述为瞬时到位。详情见position-summary.json和压缩原始记录。

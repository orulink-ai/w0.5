# AS5600 角度调试台

## 当前入口：v4位置与速度闭环、实时拖动

位置控制新增角度滑块：校准后先点击“启动并保持”，再拖动即可实时更新目标，松手保持最后角度。停机时拖动仅填写下次目标，不启动电机。范围来自芯片确认的软限位；当前默认及上限10rpm=60°/秒，拖得快时会有跟随过程。仅v4支持实时更新，v3仍可用基础控制。队列独立组件合并最新值，最多约20Hz（50ms），单请求在途；停止或失联后不恢复旧目标。当前电压幅度上限6V、校准1V，实际输出由控制器计算。调试构建输出20Hz非阻塞TRACE；[高速调试记录](../../docs/benchmarks/2026-10-24-follow-fast/README.md)说明最终10rpm和未通过的高速候选，[早期3V记录](../../docs/benchmarks/2026-10-24-follow-3v/README.md)保留此前结果。

当前使用 `g431_closed_loop` 固件，提供目标角度＋移动速度的位置控制，以及指定正反转转速的速度控制。位置到达后持续保持，没有固定5秒截止；每次显式启动由本页面每300ms续租，芯片1500ms收不到有效心跳即关闭EN。页面刷新、重连和服务重启不会接管或重启旧运动。

操作顺序：连接串口 → 显式校准 → 等待READY → 按需设零／设置范围 → 选择位置或速度 → 启动 → 立即停止。修改参数需先停止再启动。位置伺服用于定位与保持，手动转轴前先停止；本版暂不提供手拨阻力或回中交互。

手动快速转轴若触发 `OVERSPEED`，松手停稳后可点“清除超速故障 · 保持停止”，再手动启动，无需为这一故障断电重校准。复位保留校准和零点，EN仍关闭，也不会自动恢复旧动作。按钮仅用于新鲜、编码器有效、EN已关闭的超速故障；芯片还检查转轴已接近静止（≤0.2rad/s），不满足会拒绝复位，其他故障需检查原因。需同时更新支持RESET的固件、重启后端并刷新页面；当前改动仅完成离线验证。

“关闭超速保护 / 开启超速保护”用于调试手拨：当前阈值2rad/s≈115°/秒≈19rpm，目标速度上限仍为5rpm。先停止再切换，等芯片报告“已关闭”后生效；其他保护与位置保持继续有效。若已经触发超速，切换不会清除锁定，还需停稳后手动复位。设置仅对本次芯片运行有效，芯片重启后默认开启；刷新页面不会自动更改。旧固件未提供确认状态时按钮禁用，需要更新固件和重启后端。

默认相对软件范围±90°，限位基于编码器反馈。MCU状态、GPIO EN读回、相对角度与反馈速度均在面板显示。当前是电压模式FOC，没有相电流闭环，不提供精确力矩控制。旧v1/v2状态只供诊断或停止；启动与心跳必须使用v3/v4，旧stiffness参数不再接受。

构建／烧录：`python3 tools/stm32.py build --env g431_closed_loop` / `python3 tools/stm32.py upload --env g431_closed_loop`。启动调试台：`python3 tools/stm32.py dashboard --port /dev/cu.wchusbserial130`。架构和完整协议见 [控制说明](../../docs/closed-loop-architecture.md)，实测和待提交范围见 [阶段交付](../../docs/releases/stm32-basic-control.md)。

下面保留早期目标暂存、使能和开环点动说明，供独立旧环境使用，不代表当前v3控制方式。

## 历史阶段与通用使用说明

显示 AS5600 实时读数，按实际固件能力提供 PB5 使能、手动低速点动和目标暂存。使能按钮与真实 MCU 的高/低电平 ACK 相连，每次开启最多 5 秒；点动按钮与独立运动协议相连，每次约 3 秒，结束关闭 EN。0°、90°、180°、270°四个按钮仍只是旧固件的目标暂存，点动固件中禁用，不能作为定位或到位验收。

在仓库根目录启动：

```sh
python3 tools/stm32.py dashboard --port /dev/cu.wchusbserial130
```

打开 <http://127.0.0.1:8840>。串口路径以当前电脑为准，也可不带 `--port`，进入页面后刷新、选择串口并连接。服务只监听本机回环地址；浏览器通过本地服务读取串口，无需 Web Serial 设备授权。

依赖复用项目 `.venv` 中的 pyserial（PlatformIO 依赖），新环境安装方式见 `tools/requirements-stm32.txt`。没有额外的网页依赖、CDN 或构建步骤。

## 显示含义

- 角度：固件输出的 0～360° 单圈机械角度，只在有效且新鲜时显示。
- 频率：有效 PWM 的 Hz 值。
- 高电平宽度/周期：固件上报的原始 μs 数值。固件报告无效时仍可变化，不代表稳定 PWM；按最后测量上报的字段也可能暂时不变。
- 状态：串口未连接、等待数据、PWM 无效、信号有效、数据超时。
- 日志：最近 8 条实际串口文本。计数指收到的固件测量行数，不是 MCU 每个 PWM 波形的数量。

收到 `NO_PWM_OR_INVALID` 时，页面隐藏角度和频率；超过 1 秒没有新测量，所有当前测量值隐藏。后台保留有限日志，不保存长期记录；重新连接会重置本次计数。

页面的断开按钮释放串口。使用 `tools/stm32.py monitor` 或其他串口工具前先断开页面连接，避免争用。关闭浏览器标签不会停止服务或释放串口；在启动终端按 Ctrl+C 停止服务。

## 四个目标按钮与确认协议

串口双向接线：TTL RXD→PA2，TTL TXD→PA3，GND 共地；TTL 供电脚不接。用户已确认 TXD→PA3 和驱动 EN→GND。使用本例最新 `g431_as5600_uart` 固件。

- `POST /api/target`，JSON 为 `{"angle_deg":90}`；只允许整数 0/90/180/270，不接受原始串口命令或使能请求。
- 固件每秒发送 `#CONTROL,1,DISABLED,<request_id>,<target_deg>`；启动时为 `0,-1`。固件状态超过 2.5 秒、串口断开或编码器数据无效/超过 1 秒时，按钮禁用，后台也拒绝下发。
- 后台发送 `TARGET,<request_id>,<degrees>\n`。请求编号在服务启动时随机起始，用于关联响应，并降低服务重启后与芯片上次编号冲突的可能性。
- 固件回传 `#TARGET_ACK,<request_id>,STAGED,<degrees>`；只有编号和角度都匹配，HTTP 才报告成功。NACK、串口发送错误或 1.2 秒内未确认会显示错误，不自动重发。
- 固件周期状态可恢复实际暂存目标，但不能当作到位或使能确认；重连不会重发目标，芯片复位后旧目标清除。固件版本 1 只支持暂存，不存在 ARM/ENABLE 命令。

目标按编码器当前 0～360° 单圈零位表示，未增加用户零位偏置或实际运动路径规划。实际电机定位须另行确认驱动实物 EN 负载、电机极对数，并实现驱动/反馈/通信故障关断后上板验证。

2026-10-24 目标暂存阶段验收：19 项 Python 测试通过，新增四预设经伪串口传输并等 ACK 的 HTTP 集成、ACK 编号/角度匹配、超时、陈旧固件/传感器、断开重连、芯片复位和非法参数拒绝；原有测量测试保留。两套 C++ 测试（PWM 解码、目标命令解析）通过；USB/UART 固件编译通过。UART 固件经 ST-Link 下载校验后，从浏览器逐一点击 0/90/180/270，真实 MCU 均返回对应 STAGED ACK，AS5600 维持约 460Hz 有效输入。SWD 读取确认 PB5 为输出低、PA8/PA9/PA10 未配置为电机 PWM。浏览器已验证串口断开后按钮禁用、重连恢复、390px 下四按钮完整显示及无横向溢出。

实板复位验收：浏览器下发 0° 并收到 ACK 后，通过 ST-Link 软件复位 MCU；页面目标恢复为“—”、提示重新选择，随后编码器约 120° 读数恢复有效，未自动重发目标，驱动仍保持禁用。

## PB5 使能与手动点动

- `POST /api/enable`：`{"enabled":true}` / `{"enabled":false}`，严格布尔值。串口 `ENABLE,<id>,0|1`；MCU 用 `#ENABLE_ACK,<id>,0|1` 确认 GPIO 输入寄存器读回，`#ENABLE_STATUS,1,READY|FAULT,0|1,<id>` 定期报告。输出高电平不代表已测量电流或已确认驱动内部工作正常。
- 只有新鲜 READY、有效编码器且当前低电平才允许网页开启。关闭在传感器失效、固件状态过期时仍可尝试；断线/超时显示未知，不能伪造关闭成功。FAULT 仍读高时保持显示高，提示关闭 12V。
- `POST /api/motor`：`{"action":"jog"}` / `{"action":"stop"}`。串口 `MOTOR,<id>,JOG|STOP`；`#MOTOR_ACK,<id>,STARTED|STOPPED` 仅确认请求，完成以 `#MOTOR_STATUS,1,DONE,<id>` 为准。READY 或 DONE、反馈有效、EN 已确认低时可以开始。
- 点动固件负责自动开启 EN、约 3 秒截止与结束关闭 EN；新的编号可再次显式点动，同一编号不能重放，运行中不能延长。后端以状态编号高水位续号，编号耗尽不回绕启动；STOP 仍可请求。所有路径不自动重发或在重连时继续运行。
- 当前开发板由用户选择保留 R78=100Ω 并将 EN 直接接 PB5，已告知该指示灯支路可能超出推荐 GPIO 驱动条件。限时/看门狗不是电气限流，未测 GPIO 电流，不能据数字电平切换成功认定电路长期额定可靠。

使能阶段实测：`g431_enable_uart` 已 ST-Link 烧录校验，网页开启读回高、手动关闭读回低，另一次开启后自动回低，最终保持关闭。PA8/PA9/PA10 为静态低，TIM1 未启动；AS5600 约 460Hz 有效。29 项 Python 测试与四套 C++ 策略测试通过；390px 页面无横向溢出，状态过期显示未知且仍可尝试关闭。

点动阶段实板结果以 `firmware/stm32/examples/encoder_read/MOTOR_GPIO.md` 为准；使能切换成功不能代替电机实际转动验收。

## 机器人三维结构

调试台顶部现嵌入摄像头版和 1.3 寸屏幕版两套机器人 STEP 模型，可通过“模型版本”选择器切换，使用本地 Three.js 0.180.0，运行时无需联网、CDN、Node 或额外 Python 依赖。旋转/缩放、点击 CAD 零件、两个电机定位、透视及轴线显示均为本地查看操作。选择电机自动开启透视和轴线，重置视角恢复整机实体显示。模型不跟随当前单轴编码器读数，也不向硬件发送指令。

原始 STEP、副本来源及两个自由度的结构说明见 `hardware/models/README.md`。模型与机械限位分别管理，当前没有设定转动范围。

更新任一 STEP 后重新生成两套网页网格：

```sh
cd tools/cad
npm install
npm run convert
```

仅转换工具使用 `occt-import-js`（LGPL-2.1）；浏览器只加载 Three.js（MIT，许可证位于 `static/vendor/three/LICENSE`）和已生成的几何数据。工具以 0.12 mm 线性离散公差、0.25 rad 角度参数生成摄像头版约 791 KiB、屏幕版约 647 KiB 几何缓冲，保存来源 SHA-256。更换模型后需要重新核对 `robot-joints.json` 或 `robot-screen-joints.json` 中电机网格索引和解析轴线，不能沿用旧模型索引推断新结构。

若启动服务后才修改了静态资源路由，需要重启服务。独立预览可使用 `.venv/bin/python tools/encoder_dashboard/server.py --http-port 8841`，不带串口参数。验证：`python -m unittest discover -s tools/tests -p test_robot_viewer.py -v`。

切换功能验证：`node tools/tests/test_robot_model_loader.mjs`，覆盖旧请求晚到、请求失败与重新加载。两套模型均有源文件哈希、几何范围和电机索引验证。直接打开屏幕版可使用 <http://127.0.0.1:8841/?model=screen>。


### 材质与屏幕表情预览

两种模型默认使用暖白哑光塑料外壳、深灰金属支架、金属电机和玻璃镜头/屏幕的概念材质，可通过“外观”切回 CAD 原色。这是设计效果预览，不代表实物最终材料。材质配置独立保存在 `static/robot-finishes.mjs`；本地 RoomEnvironment 提供环境反射，地面接收阴影，无需下载贴图。

屏幕版正面叠加 CanvasTexture 表情，显示青绿色眼睛、微笑和间歇眨眼，支持关闭；透视时隐藏表情以便查看电机。表情平面依据屏幕网格 10 的前表面（三角形 42–43）定位，中心约 `(33.35953, 15.20264, 81.46675)` mm，法向 `(0, -0.93969262, 0.34202014)`。模型切换清理表情纹理和定时器；系统要求减少动态效果时保持静态眼睛。当前只在网页显示，没有向实体屏幕烧录表情。

验证：`node tools/tests/test_robot_finishes.mjs` 检查角色映射与高亮/透视后材质恢复；`test_robot_viewer.py` 检查本地资源供应；浏览器检查实际贴合、自动眨眼、开关和两个版本切换。


### 可切换的桌面场景

“场景”提供科技桌面（双机/单机）、暖木桌面（双机/单机）和简洁展台。科技桌面有石墨灰台面、银色键鼠、细边框显示器、原创蓝青壁纸、暖背光和台灯；暖木桌面保留橡木、笔记本、铅笔、陶瓷咖啡杯和绿植。两套装饰分别封装在 `static/robot-desktop.js` 与 `static/robot-warm-desktop.js`，独立管理材质、纹理和可见性，固定复用各一个实例。配置位于 `static/robot-scene-config.mjs`。全部纹理本地生成，不依赖外部素材。

所有物件统一毫米单位，机器人保持原始约 105–108 mm 高度。科技桌面设备采用常见尺寸作为场景设计基准：显示器机身约 606 mm 宽、含底座约 454 mm 高，键盘约 308 × 106 mm，鼠标约 66 × 106 mm；这些是场景道具估算尺寸，不是特定商品规格。暖木场景杯身约 80 mm 直径、92 mm 高，笔记本约 90 × 140 mm。`node tools/tests/test_robot_scenes.mjs` 使用实际 Three.js 世界包围盒检查设备尺寸、桌面落地位置和资源释放。

双机场景中摄像头版在左，屏幕版在右，间距 132 mm；两套 CAD 网格只作平移，眼睛与转轴随各自父组移动。通过“查看版本”选择电机操作对应的机器人。第二台装配体由 `static/robot-replica.js` 管理，版本切换释放旧几何、材质、表情纹理和定时器。装饰不参与 CAD 零件选取，不改变硬件或通信。

选中的场景保存到 URL：`?model=screen&scene=warm-pair` 可直接打开暖木双机场景，`scene=pair` 为科技双机场景，`warm-desk` / `desk` 为相应单机场景，`studio` 为简洁展台。刷新保留场景，未知场景名回退到科技双机。窄屏优先保证机器人可见，部分装饰可能位于画面之外。


### 场景互动动画

“桌边互动”为约 18 秒的循环。0–4.7 秒向外转头 35°并停住观察，再转向另一侧；4.7–8.9 秒两台向内转头 48°，摄像头版先低头 18°，屏幕版晚 0.9 秒低头 20°回应；回正后于 11.4、13.2 秒分别开始 12°、18°的两次点头，中间完整回正并停顿；最后安静陪伴。屏幕眼睛提前看向目标，眨眼跟随点头。幅度用于网页动作表现，不代表未知的实际机械限位。

提供播放/暂停、动作归位、互动特写、24fps 时间轴和前后逐帧。特写在页面尺寸变化后保持。普通设置下加载完成自动播放，系统要求减少动态效果时等待显式播放。单机保留同等幅度的观察和点头，不使用同伴延迟。

`robot-rig.js` 围绕两个已测 CAD 轴线重组层级：底座与下电机本体固定，上支架与上电机随 yaw 旋转，头部紧固件、摄像头/屏幕与头壳随 pitch 旋转；屏幕表情附着在头部节点。零姿态保留原 CAD 坐标和整机尺寸，两台仍相距 132 mm。点击电机、透视或显示转轴会暂停并恢复零姿态，以便结构检查。

`robot-motion.mjs` 只生成两轴姿态、视线和眨眼时序；`robot-motion-clock.mjs` 管理唯一的约 24fps 帧循环，暂停保留时间，后台/加载时冻结且恢复不追赶时间，归位清零。表情也使用同一时间轴，暂停和拖动不会触发随机眨眼。页面离开时取消帧循环，往返缓存恢复时重启；模型切换清理旧装配体与表情计时器。动画无串口/API 写入，不发送真实运动命令。

验证：`node tools/tests/test_robot_motion.mjs`（幅度、循环连续、双机时序）；`test_robot_rig.mjs`（零姿态不变、底座固定、头部与眼睛共动）；`test_robot_motion_clock.mjs`（暂停、归位、可见性恢复与无重复帧循环）。浏览器验证实际自动播放、暂停、归位、查看转轴和场景切换。

2026-10-24 动作复盘：旧版 ±16° 转头、7° 点头虽连续，但默认桌面画面难以读出意图，工程测试不能作为动作表现力评分。新版保留明确的定向停顿与先后回应，并导出 433 帧及 [18 秒实际渲染预览](../../docs/animation-review/action-v2.mp4)。验收包含动作可辨的关键姿态、时序与真实网页渲染，未据此自评“100分”。
